# `preflight`

**When:** the first reply of every be•do chat

**Command:** `preflight`

line one is the chat's title — put it alone, first, in a code box, and save it as the chat's name in the same reply (`set_session_title` on this session, from `get_session`; where no tool can rename the chat, she renames it). Then the clock and the base. A `STOP` means no read or write until the base is right. The `first` line names yesterday's my day page: final and QA'd, with its link, or what is still missing, then offer to finish it. **The day behind is retired** (8 Nov 2026, her word: I'm just doing my day), so never offer one, and when `first` says *not checked*, say nothing about whether yesterday is finished

**`preflight` also names every active amendment no check in code enforces**:
`⚠ rule on paper only: …`. The map from amendment to check is
`amendment_checks` in the `facts_local` settings row (record id → check names from
`core/bedo_rules.py`, or `["judgment"]`). A line there is a rule that still
depends on a chat remembering: tell her once, and add it to the backlog.

**A branch chat runs `preflight --kind branch --n N --what "GLYPH what it does"`**
(12 Nov 2026). Line one is its title: `▶️↳1112.4 🌳 Thu 👁️ my day page`. `N` is
the order the branch opened that day: count the day's sessions tagged
`bedo:MMDD`, this one included, and never take the number from memory. With no
`--n` the title carries a `?` and a line says where the number comes from. A
branch gets the clock and the base, then two lines: it writes its own rows,
each through `entry` first, and it closes when its objective is met or at the
day's dusk close. It is not handed the morning line, what the day owes, or the
rules on paper: those are the my day chat's.
