# `sweep`

**When:** the dusk close, before `dayqa`; and on call, any time a day's rows came from somewhere that can't run `entry`

**Command:** `sweep YYYY-MM-DD` (today when no date is given)

**Rows go through the entry check, whoever writes them** (J17; her yes, 24 Nov 2026). Duet writes its captures straight to the stream, because a Code session for every note would be too slow. So the check comes to the rows: one read of the day, and each row through the rules `entry` applies before a write. It reads; it never writes.

Two kinds of line under each row that has something to fix:

- **`be•do`**: what a rule deduces by itself, printed as `field: empty → value` or `field: empty — deduced value` (a device, a wellness, the people at home, a point row's end). Write the value in place through the connector. No question for her.
- **`FIX`**: what a rule can't settle: a row with no practice, a status or choice the base doesn't carry, a plan that names people, a gratitude that isn't one bullet a thing. These go on her dusk list with `dayqa`'s, one line each, with be•do's best guess beside it.

**The capture rules** (J17, 24 Nov 2026) are applied here, so a row with no practice is rarely a question: a passing remark is a 📝 log, a longer reflection a 📒 journal, a talk with someone 🗣️ face-to-face, and a note with a video or podcast link takes that kind. A gratitude is set one bullet a thing, her words kept (the text is under `set` in `--json`). Only a note on something she is taking in with no link to say what, or a row no rule fits, comes to her. Her answer then goes into the judgment file as the next rule, and into `capture` in the facts when code can apply it.

A rule about the moment of writing is not asked of a row already in the stream: the key the base fills on every row, and which weekly base it belongs in.

`sweep  Mon 23 Nov: 30 rows, every one passes the entry check` is the answer on a clean day. After the writes, run it again: the `be•do` lines should be gone.

**What Duet's instructions carry**, once:

> When you write a row to the stream, write it with typecast off and copy every select value (status, practice, wellness, device, emotion, attention) exactly as the base already has it, glyph and spacing included. If Airtable refuses the write, fix the value and try again; never let it make a new choice. Every row gets a practice: a passing remark is 📝 log, a longer reflection in my words is 📒 journal, a talk with someone is 🗣️ face-to-face. A note about something I'm watching, reading or listening to goes on that thing's own row with its link, not a new row. A gratitude is one bullet per thing. When I say I did something, find its open action and mark it ✅ done; don't log it again. If none of these fits, ask me once.
